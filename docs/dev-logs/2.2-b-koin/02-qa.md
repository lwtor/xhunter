## Q1：spec 第二节"核心概念速查"里的 Module 那段代码是什么意思？我具体要怎么操作？

**时间**：2026-06-03 14:57

### 误会澄清

spec 第二节（"核心概念速查"）**不是让你照着抄的代码**，是**先讲清楚概念**，免得后面看 B-1/B-2/B-3 时一脸懵。

- 第二节 = **知识铺垫**（读懂就行，不动手）
- 第三节 B-1 / B-2 / B-3 = **真正的操作步骤**（照着改文件）

所以那段 `val sharedModule = module { single<RootComponent> { ... } }` 你**完全不用照抄**——它只是帮你理解"Module 是干嘛的"。真正要写的 Module 代码在 spec 第 122-138 行（B-2 那段），用的是 `factory` 不是 `single`，原因 spec 里也写了（Activity 重建语义）。

### 那段示例代码到底在讲什么？

逐行翻译：

```kotlin
val sharedModule = module {                                // 定义一个名叫 sharedModule 的"对象配方清单"
    single<RootComponent> { (ctx: ComponentContext) ->     // 配方第 1 条：当有人要 RootComponent 类型时
        DefaultRootComponent(componentContext = ctx)       // 用 DefaultRootComponent 这个具体类来造，把外面传进来的 ctx 塞进去
    }
}
```

打个比方：

| 现实世界 | Koin 世界 |
| --- | --- |
| 餐厅的菜单 | `module { ... }` |
| 菜单上的某道菜（"宫保鸡丁"） | `single<RootComponent> { ... }` |
| 这道菜的做法（食材+步骤） | lambda 里 `DefaultRootComponent(...)` |
| 顾客点单 | `getKoin().get<RootComponent>()` |
| 厨房按菜谱出菜 | Koin 容器调 lambda 返回实例 |

`single` vs `factory` 区别：

- `single`（单例）：菜做好放保温台上，下次有人点就直接端走，**一份反复用**。适合无状态工具（如全局 Logger、Repository）
- `factory`（工厂）：每次点都现做一份新的。适合**带运行时上下文**的对象（如本步的 `RootComponent`，每次 Activity 重建都要新实例）

### 你具体应该怎么操作？

**忽略第二节（概念速查），直接跳到第三节 B-1 开始动手**：

1. **B-1 加依赖**（spec 第 89-118 行）—— 改 3 个文件：`gradle/libs.versions.toml`、`shared/build.gradle.kts`、`androidApp/build.gradle.kts`，照着 spec 里贴的代码片段加就行。改完点 AS 右上角 "Sync Now" 让 Gradle 同步。
2. **B-2 写 Koin Module**（spec 第 120-143 行）—— 新建一个文件 `shared/src/commonMain/kotlin/com/lwtor/xhunter/di/SharedModule.kt`，把 spec 里那段代码（`factory<RootComponent> { ... }` 那段）直接复制进去。
3. **B-3 三件套**（spec 第 145-225 行）：
   - B-3.1 新建 `XhunterApplication.kt`（spec 第 149-171 行）
   - B-3.2 改 `AndroidManifest.xml` 加 `android:name=".XhunterApplication"`（spec 第 173-184 行）
   - B-3.3 改 `MainActivity.kt` 用 Koin 取 `RootComponent`（spec 第 186-216 行）
   - B-3.4 顺手清理 `MainScreen.kt` 旧 Preview 残留（spec 第 218-225 行）

每一小步 spec 里都有完整代码片段，照着抄+改就行。

### 推荐的动手顺序

我建议你按 B-1 → B-2 → B-3 的顺序**一小步一跑**，不要一次改完所有再 Sync：

1. 改完 B-1 → Gradle Sync 一次（确认依赖能下下来）
2. 写完 B-2 SharedModule.kt → AS 不报红就过（这一步不会跑起来，纯声明）
3. B-3 全部完成 → 跑模拟器 → 看 logcat 过滤 `Koin` 关键字，能看到 `[Koin] Started 1 module(s)` 就对了

如果中间任何一步报错，贴给我，我在这份 qa 文档继续追加。

## Q2：跑起来闪退，报 `IllegalStateException: You can 'consumeRestoredStateForKey' only after the corresponding component has moved to the 'CREATED' state`

**时间**：2026-06-03 15:12

### 完整堆栈关键行

```
Caused by: java.lang.IllegalStateException: You can 'consumeRestoredStateForKey' only after the corresponding component has moved to the 'CREATED' state
    at androidx.savedstate.internal.SavedStateRegistryImpl.consumeRestoredStateForKey(SavedStateRegistryImpl.kt:48)
    at com.arkivanov.essenty.statekeeper.AndroidExtKt.StateKeeper(AndroidExt.kt:26)
    at com.arkivanov.decompose.DefaultComponentContextBuilderKt.defaultComponentContext(DefaultComponentContextBuilder.kt:87)
    at com.lwtor.xhunter.MainActivity.onCreate(MainActivity.kt:18)
```

### 根因（AI 之前 spec 写错了，致歉）

`MainActivity.kt:18` 是 `val componentContext = defaultComponentContext()`，调用时 Activity 还没进入 `CREATED` 状态。

- **2.2.a 时 spec 写的是**：`defaultComponentContext()` 必须在 `super.onCreate(savedInstanceState)` **之前**调用
- **这是旧版 Decompose（≤ 2.x）的规矩**。
- **Decompose 3.x 改了行为**：`defaultComponentContext()` 内部会调 `SavedStateRegistry.consumeRestoredStateForKey(...)`；这个方法要求 owner（Activity）已经进入 `CREATED` 状态，而进入 CREATED 的时机就是 `super.onCreate(savedInstanceState)` 执行完成时。
- 所以新版的正确顺序是 **`super.onCreate` → `defaultComponentContext()`**，正好和旧版反过来。

2.2.a 当时之所以没崩，是「巧合」——那次的项目 + Decompose 版本恰好走到了不依赖 `SavedStateRegistry` 的代码路径；2.2.b 没改这部分代码，但运行时偶现/必现都属于这个潜在 bug 暴露。Decompose 官方 sample 现在也都是 `super.onCreate` 之后调。

### 修复（仅改 `MainActivity.onCreate` 内部 2 行顺序）

把：

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    val componentContext = defaultComponentContext()   // ❌ 太早
    super.onCreate(savedInstanceState)
    enableEdgeToEdge()

    val root: RootComponent = getKoin().get { parametersOf(componentContext) }
    setContent { App(rootComponent = root) }
}
```

改成：

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    enableEdgeToEdge()

    // Decompose 3.x：必须在 super.onCreate 之后调用，否则 SavedStateRegistry 还没 ready
    val componentContext = defaultComponentContext()
    val root: RootComponent = getKoin().get { parametersOf(componentContext) }
    setContent { App(rootComponent = root) }
}
```

只动 `MainActivity.onCreate` 内部，其他文件（SharedModule / XhunterApplication / AndroidManifest）都不动。

### 顺手核对

- 注释也一起更新（旧注释「必须在 super.onCreate 之前」已不正确）
- spec 第 200-216 行已同步修正，并加了 ⚠️ 提示
